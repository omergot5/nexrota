# Requirements: NexRota

**Defined:** 2026-09-17
**Core Value:** אדם שמקבל את האפליקציה לידיו מסיים סידור שבועי מלא בלי שאף אחד יסביר לו כלום — ומה שהמערכת אומרת לו על עצמה הוא נכון.

**מקור:** מפרט עבודה חיצוני (`shift-app-spec-for-claude-code.md`, 2026-09-17) — 9 נושאים, מסודרים כאן ב-8 קטגוריות לפי סדר העדיפות שהמפרט עצמו קובע (נושא 2+3 אוחד לקטגוריה אחת).

## v1 Requirements

### RESVIEW — מבט משאבים כאב-טיפוס עיצובי

- [x] **RESVIEW-01**: מנהל שבונה שבוע ("בניית שבוע") רואה את אותו דפוס מבני של מבט משאבים — שורת עמדה → עמודות משמרת מסודרות → שמות משובצים
- [x] **RESVIEW-02**: מבט שבועי ביומן עוצב מחדש לפי אותו דפוס בדיוק (מבנה שורות/עמודות, טיפוגרפיה, ריווח)
- [x] **RESVIEW-03**: הרכיב המשותף תומך במספר משמרות דינמי לעמדה — לא הרדקוד ל-3 (כפי שמבט משאבים מציג היום) או ל-4 (כפי שתרחיש הצבעים מניח)

### COLOR — צבעים וסדר משמרות (עמדות + תמונה משותפת)

- [x] **COLOR-01**: תמונת השיתוף (canvas) המיוצאת קריאה וחדה בבדיקה ידנית בגודל שיתוף רגיל (וואטסאפ) — נבדקת רזולוציה/DPI/פורמט הייצוא
- [x] **COLOR-02**: תווית עמדה/משימה מוצגת בשחור אחיד ומודגש (bold/רקע קבוע) בכל תצוגה, כולל תמונת השיתוף — לא עוד צבע נפרד לכל עמדה
- [x] **COLOR-03**: כל כפוף ממשיך להיות מסומן בצבע אישי משלו, בלי שינוי מההתנהגות הקיימת
- [x] **COLOR-04**: משמרות מוצגות בסדר כרונולוגי לפי שעת התחלה בפועל בכל תצוגה (כולל תמונת השיתוף) — הסדר לא הרדקוד לפורמט 4×6 שעות; עמדה עם מספר/אורך משמרות אחר עדיין ממוינת כרונולוגית

### WEEKBUILD — בניית שבוע (שינוי שם) + תמונת מצב שבועית

- [x] **WEEKBUILD-01**: במצב army, כל מופע UI של "בניית סד״כ" (`terms.js` `nav.shifts`) משתנה ל"בניית שבוע" — מאחד את אוצר המילים מול המצב הגנרי
- [x] **WEEKBUILD-02**: מסך "תמונת מצב שבועית" חדש קיים, ממוקם מיד אחרי "בניית שבוע" בניווט/בתפריט
- [x] **WEEKBUILD-03**: מנהל יכול לנווט בין שבועות בחצים (קדימה/אחורה) בתמונת המצב
- [x] **WEEKBUILD-04**: מנהל יכול לצפות במה שכבר משובץ בפועל ("מה שיש עד עכשיו") דרך כפתור ייעודי
- [x] **WEEKBUILD-05**: מנהל יכול לבחור עמדה/משימה ספציפית ולראות בדיוק אילו שעות היא תפוסה על פני השבוע, בלוח שבועי ממוקד נפרד מהתצוגה הכללית

### REST — לוח זמן מנוחה + כפתור הדגמה מפורש

- [x] **REST-01**: לוח "זמן מנוחה" מוסר מלוח הבקרה הראשי (Dashboard)
- [x] **REST-02**: לוח "זמן מנוחה" מוצג בתוך "כפופים שלי"
- [x] **REST-03**: כפתור "הדגמה" מפורש (מסומן בבירור) מחליף כל מילוי סמוי/אוטומטי של נתוני הדגמה
- [x] **REST-04**: לחיצה על כפתור ההדגמה פותחת דיאלוג פרמטרים (לפחות מספר אנשים להדגמה) לפני יצירת הנתונים — אין יותר מילוי "בשקט"

### MORE — ביקורת תפריט "עוד" מול לוח הבקרה

- [x] **MORE-01**: קיימת טבלת ביקורת (בקוד/ב-PR description) שממפה כל פריט תחת "עוד" (כיום: swaps, tasks, positions, resources, analytics) → מיקום נוכחי → כפול? → המלצה
- [x] **MORE-02**: קיצורי דרך רלוונטיים שזוהו בביקורת נוספו ללוח הבקרה
- [x] **MORE-03**: כפילויות מיותרות שזוהו בביקורת הוסרו, בלי לשבור פיצ'ר קיים

### INLINE — עריכה אינטואיטיבית + ניקוי הדגמה + באג מצב השבוע

- [x] **INLINE-01**: מנהל יכול להוסיף/למחוק שיבוצים ישירות בתוך "בניית שבוע" (inline, בלי לצאת מהמסך/לצלול לתפריטים)
- [x] **INLINE-02**: רשומות שיבוץ נושאות דגל `is_demo` (או שקול) שמבחין בבטחה נתוני הדגמה מנתונים אמיתיים
- [x] **INLINE-03**: קיימת פעולה "מחק נתוני הדגמה לשבוע זה" — לחיצה אחת מוחקת רק רשומות `is_demo` של השבוע הפעיל, בלי לפגוע בנתונים אמיתיים
- [x] **INLINE-04**: "מצב השבוע" משתקף נכון ומיידית אחרי כל שינוי (הוספה/מחיקה/מחיקת-הדגמה) — תיקון הבאג הקיים, מאומת בתרחיש שחזור מלא

### CONFIRM — אישורי פעולות קריטיות (רוחבי)

- [x] **CONFIRM-01**: קיימת קומפוננטת אישור גנרית אחת (טקסט דינמי לפי הפעולה, כפתורי אשר/בטל), בשימוש חוזר — לא לוגיקת אישור כפולה בין מסכים
- [ ] **CONFIRM-02**: הפצה/פרסום סדר שבועי עוברת דרך דיאלוג האישור
- [ ] **CONFIRM-03**: מחיקת שבוע ומחיקת נתוני הדגמה עוברות דרך דיאלוג האישור
- [ ] **CONFIRM-04**: ביטול הפצה קיימת עוברת דרך דיאלוג האישור
- [ ] **CONFIRM-05**: כל פעולה הרסנית נוספת שאותרה בסקירת הקוד (מחיקות/דריסות/פעולות bulk) מחוברת לדיאלוג האישור
- [ ] **CONFIRM-06**: "בטל" בדיאלוג חוזר למצב קודם בלי אפקט צד

### BUG — ביטול הפצה לא עובד אחרי פרסום

- [ ] **BUG-01**: תרחיש "פרסם שבוע → נסה לבטל הפצה" משוחזר בפועל ומתועד (שגיאה שקטה/שגיאת שרת/כלום לא קורה)
- [ ] **BUG-02**: שורש הבעיה מזוהה ומתועד (מה בדיוק שבר את הפיצ'ר — `setPublished` ב-`api.js` כבר בודק RLS/ריק-שורות ב-`.select()`, כך שהחשד עובר לזרימת ה-UI/state סביב הקריאה לו)
- [ ] **BUG-03**: "ביטול הפצה" עובד בצורה אמינה אחרי פרסום, מאומת בתרחיש שחזור מלא בדפדפן — לא רק בדיקה שטחית
- [ ] **BUG-04**: נוספה בדיקה (automated test או checklist ל-QA ידני) שמונעת רגרסיה חוזרת של אותו באג
