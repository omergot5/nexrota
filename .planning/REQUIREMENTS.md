# Requirements: NexRota — אבן דרך ב'

**Defined:** 2026-08-21
**Core Value:** אדם שמקבל את האפליקציה לידיו מסיים סידור שבועי מלא בלי שאף אחד יסביר לו כלום — ומה שהמערכת אומרת לו על עצמה הוא נכון.

## v1 Requirements

### FAIR — מדד הוגנות אחד

הבטחת המוצר היא "נטל, לא ספירה". היא נשמרת בניקוד וב-`fairness.js`, ודולפת בשני מקומות.

- [ ] **FAIR-01**: מעבר האיזון מעביר משמרת מהעמוס לפנוי לפי **נטל**, ולא לפי ספירת משמרות
- [ ] **FAIR-02**: ציון ההוגנות שהמנהל רואה על המסך מחושב מנטל, ולא מספירת משמרות
- [ ] **FAIR-03**: סף העצירה (היום `gapSize < 2`) ומקדם השונות (היום `× 15`) נגזרים מחדש ליחידות נטל — לא מוחלפים כפי שהם
- [ ] **FAIR-04**: `npm test` נכשל אם ציון ההוגנות המדווח סותר את פיזור הנטל בפועל
- [ ] **FAIR-05**: המספר שהמשתתף רואה בשורת ההוגנות שלו הוא אותו מספר שהמנוע חילק לפיו
- [ ] **FAIR-06**: גרסת ה-service worker מוגדלת בשחרור, כדי שדפדפן לא יגיש נוסחה ישנה לצד חדשה לאותו סידור

### UNIF — משימה ומשמרת במנוע אחד

היום `checkHardConstraints` רואה רק משמרות ו-`findConflicts` רק משימות. אדם יכול להיות במטבח ובתורנות לילה באותו יום.

- [x] **UNIF-01**: משימה חדשה נושאת שעת התחלה ושעת סיום, ולא רק טווח תאריכים
- [x] **UNIF-02**: משימה עם שעות נספרת במנוחה, ברצף, בתקרה השבועית ובנטל — בדיוק כמו משמרת
- [x] **UNIF-03**: פונקציית חפיפה אחת משרתת משמרות ומשימות; ההשוואה ברמת מילישניות בשני המקרים
- [x] **UNIF-04**: משימה שנוצרה לפני המיגרציה נשארת מחוץ למנוע וממשיכה לעבוד בדיוק כמו היום
- [x] **UNIF-05**: המנהל רואה בבירור אילו משימות נספרות במנוע ואילו קפואות מחוץ לו
- [x] **UNIF-06**: מטריצת ההתנגשויות ממשיכה לחסום זוגות סותרים אחרי האיחוד, ללא נסיגה

### QUAL — כשירויות

- [ ] **QUAL-01**: לכל אדם סט שטוח של קטגוריות שהוא רשאי לבצע
- [ ] **QUAL-02**: אדם חדש כשיר לכל הקטגוריות בלי שהמנהל נגע בכלום
- [x] **QUAL-03**: משמרת ומשימה נושאות שדה `category` — סוג העבודה — נפרד מ-`type` שהוא שעה ביום
- [x] **QUAL-04**: אדם שאינו כשיר לא ישובץ באף מסלול: שיבוץ אוטומטי, מעבר איזון, שיבוץ ידני, ואישור בקשת החלפה
- [ ] **QUAL-05**: חסימת כשירות אינה ניתנת לעקיפה, גם לא על ידי המנהל, וגם לא עם נימוק
- [x] **QUAL-06**: הסיבה לחסימה מגיעה דרך אותו ערוץ הסבר שכל אילוץ אחר משתמש בו — לא חסימה שקטה
- [x] **QUAL-07**: המנהל רואה את הכשירויות של אדם בזמן שיבוץ ידני, בלי לעזוב את המסך
- [x] **QUAL-08**: משבצת שנשארה ריקה מבחינה בין "אין כשירים" לבין שאר סיבות החסימה

### POS — עמדות קבועות

- [ ] **POS-01**: מנהל מגדיר עמדה שנכנסת לכל שבוע אוטומטית
- [ ] **POS-02**: שיוך אדם לעמדה מצהיר שהוא כשיר לה — הוא אינו משובץ אליה בכך
- [ ] **POS-03**: העמדה מתממשת לשורות שבועיות עם מזהים דטרמיניסטיים
- [ ] **POS-04**: הרצה חוזרת על אותו שבוע מייצרת בדיוק אותן שורות, ללא כפילויות
- [ ] **POS-05**: המנהל רואה "מי כשיר לעמדה" בנפרד מ"מי עובד בה השבוע"

### BOARD — לוח מאוחד

- [ ] **BOARD-01**: לוח אחד מציג משמרות ומשימות יחד, ממוין ומסודר
- [ ] **BOARD-02**: לכל עמדה יש תצוגה שבה רואים את הלוז שלה רץ קדימה
- [ ] **BOARD-03**: הלוח מסמן חסימת כשירות באותו אופן לשני סוגי הפריטים
- [ ] **BOARD-04**: אדם שלא ראה את האפליקציה מעולם מבין מה הלוח מראה, בלי הסבר

## v2 Requirements

- **QUAL-V2-01**: תוקף לכשירות (רישיון שפג) — צורת נתונים אחרת (חלון תוקף, לא בוליאני), וגוררת התראות שנדחו
- **QUAL-V2-02**: עורך כשירויות מלא — עריכה קבוצתית ומטריצת כשירויות
- **QUAL-V2-03**: אכיפת כשירות בצד השרת (RLS או טריגר) — הפיכת ההבטחה למוחלטת גם מול קריאה ישירה ל-API
- **NOTF-V2-01**: התראות (push/SMS/וואטסאפ)
- **ABSN-V2-01**: היעדרויות כישות נפרדת (חופשה/מחלה)

## Out of Scope

| Feature | Reason |
|---------|--------|
| היררכיית תפקידים יורשת | עובדת לצבא ושוברת את המסעדה. שף ומלצר הן קבוצות זרות, לא מדורגות. סט שטוח פותר את שתיהן — קרבי פשוט נושא את איחוד התגים. אף מתחרה שנבדק לא מימש היררכיה אמיתית. |
| עקיפת חסימת כשירות עם נימוק | עקביות היא כאן האינסטינקט השגוי. מטריצת ההתנגשויות היא השערה על העולם ולכן ניתנת לעקיפה; כשירות היא עובדה על האדם. מלצר לא יכול לבשל, ואין נימוק שמשנה זאת. |
| מילוי שעות למשימות ישנות | הזרקת שעות שאיש לא הזין מרעילה את חישוב הנטל ומפעילה אילוצים שמעולם לא נועדו לראות נתוני משימות. הן קופאות מחוץ למנוע. |
| שער הקמה לפני שיבוץ ראשון | ברירת מחדל "כשיר להכול" קיימת בדיוק כדי שלא יהיה שער כזה. דרישה שמחייבת הקמה לפני ההרצה הראשונה נכשלת במבחן הכניסה. |
| מודל ארגון והזמנות | `team_code` נשאר מפתח הבידוד היחיד במחזור הזה. חסם אמיתי למכירה לארגון — ידרוש מחזור משלו. |
| פיצול `useGuardian.js` | `actions` חייב להישאר יציב רפרנציאלית; פיצול שובר בדיוק את התכונה הזו. |
