**1. `src/lib/dates.js` — three new exports, appended after `withEngineTasks`.**

`rangeTextHe(task)` — move the formatting rule that today lives privately in `views.jsx`: when `task.startDate` and `task.dueDate` both exist and differ, return `` `${formatDateHe(task.startDate)} – ${formatDateHe(task.dueDate)}` ``; otherwise return `formatDateHe(task.dueDate)` when `dueDate` exists, else the empty string. Same separator, same spacing, same fallback — the string must be indistinguishable from what the task list prints today (P-02).

`boardShapeOf(task)` — the display-only sibling of `taskAsShiftShape`. Return `null` when `isTaskEngineEligible(task)` is true (that item already arrives through `withEngineTasks` and must not be duplicated), and `null` when the task has no anchor date at all. Otherwise return a flat object carrying `id`, `date` set to the anchor `task.dueDate || task.startDate`, `timeless: true`, `label` falling back to `"משימה"` exactly as `taskAsShiftShape` does, `assignedGuards` from `task.assignees || []` — that field name and not `assignees`, so the board has one people field for every item type — `category` falling back to the empty string, `type: "task"`, `startDate`, `dueDate`, and `positionId` (null when absent). It must not set `startTime` or `endTime` at all: absence is the signal, and a fabricated hour is forbidden by the milestone's own out-of-scope table. The anchor expression `dueDate || startDate` is the idiom already used in `taskInterval`, `workingGuardIdsForWeek` and `PositionsScreen` — reuse it, do not invent a different anchor and do not spread a multi-day item across every date it spans (no call site in this codebase does that today).

`boardItemsForDates(shifts = [], tasks = [], dates = [])` — the single board merge. Build the timed pool from `withEngineTasks(shifts, tasks)` and the timeless pool from `tasks.map(boardShapeOf).filter(Boolean)`. Return `{ days, outside, undated }` where `days` is one entry per element of `dates`, **in the given order**, shaped `{ date, timeless, timed }`; `timed` is sorted ascending by `startTime` with `localeCompare` and tie-broken by `id` with `localeCompare`; `timeless` is sorted by `id` with `localeCompare`. `outside` is the count of pool items whose `date` is not in `dates`; `undated` is the count of tasks with no anchor date. Every sort must be explicit — the array order Postgres happened to return is never a sort (CLAUDE.md iron rule 1, and the rule `positions.js` states about itself). Guard against non-array inputs the same way `withEngineTasks` does.

Document in a header comment above the trio why the board needs a second adapter at all and why it may never feed the engine, referencing UNIF-04.

**2. `scripts/verify-board.mjs` — new file, copying `verify-positions.mjs`'s convention exactly.**

Import from `../src/lib/dates.js`. Inline literal fixtures for one week (pick a fixed Sunday such as `"2026-09-06"` and its seven dates — never a value derived from the current clock). The fixture must contain, at minimum: two ordinary shifts on the same day with different `startTime`s; one engine-eligible task (single day, both hours); one frozen single-day task (a `dueDate`, no hours); one multi-day task (`startDate` earlier than `dueDate`, no hours); one weekly-shape position row shaped exactly as `plannedRowsForWeek`'s `weekly` branch emits it — `startDate` the Sunday, `dueDate` the Saturday, both times null; one task whose anchor date falls outside the week; and one task with neither `dueDate` nor `startDate`.

Assertions:
  - the accounting total holds — the sum over `days` of `timeless.length + timed.length`, plus `outside`, plus `undated`, equals `shifts.length + tasks.length` exactly;

  - `rangeTextHe` returns a two-date sentence for the multi-day task and a single-date sentence for a single-day task.

Within a day: timeless items first, then timed items, in the order `boardItemsForDates` already produced. Do not re-sort in the component — the ordering contract lives in the pure function and is tested there.

Row: `bg-surface-sunken` with `ring-1 ring-inset ring-hairline`, `rounded-xl`, `p-2.5`, `flex items-center gap-3` (P-03). Then the label at `text-sm font-semibold text-content` with `truncate`. Then, in a `text-[11px] text-faint` meta line carrying `data-numeric`: for a timed item a `clock` icon at size 11 followed by `{startTime}–{endTime}`; for a timeless item a `calendar` icon at size 11 followed by `rangeTextHe(item)`, plus the neutral engine-exclusion badge. Copy that badge verbatim from `TaskRow` — `Badge` with `tone="neutral"` and `icon="lock"`, its text, and its wrapping `title` tooltip sentence — do not paraphrase either string. Trailing element is `People` for `item.assignedGuards`. `People` is currently private to `views.jsx`; export it from there and import it here rather than writing a second avatar stack.

Empty state: when every day group is empty, render `EmptyState` with `icon="inbox"` and the `empty` prop's `title`/`body`, falling back to the manager copy — heading `"השבוע עדיין ריק"`, body `"בנה משמרות או משימות, והלוח ייבנה מעצמו — או תתחיל מ'תסדר לי את השבוע'."`.
