<objective>
Bring the third supervisor-facing fairness surface — the reports screen — onto the same unit as the engine, and close the inventory gate that was structurally blind to it.

`src/components/SupervisorApp.jsx:39` labels the reports nav item `hint: "עומסים, לילות והוגנות"` — loads, nights **and fairness**. The screen behind that label, `src/components/supervisor/Analytics.jsx`, computes per-person workload with the exact formula this phase exists to eliminate: `total: mine.length` (a shift count) and `hours: Math.round(...)` (unweighted hours), rendered side by side in the per-person table at lines 169–175. Neither 01-01 nor 01-02 touches this file. The phase goal line is "נטל, בכל מנוע **ובכל מסך**" — every engine and every screen — and this screen currently contradicts it while advertising fairness in its own nav label.

This plan does four things. It moves the reports table onto weighted load by delegating every figure to `teamAverages()`, the pure function `GuardApp.jsx` already uses, so the reports screen cannot hold a private formula. It resolves the Recharts colour constraint properly rather than by deletion: the existing code comment states the real reason those five colour values are hardcoded — *"Recharts styles its axes and tooltips through JS props, not CSS, so it cannot read our custom properties — it has to be told the theme"* — and that constraint is true, so the capability moves into a design module that reads `tokens.css` at runtime instead of being removed. It widens the fairness-surface inventory gate to cover `shiftLoad`, `shiftHours` and the new `loadTable`, so a workload table measured in the wrong unit cannot appear in `src/components/` unseen again. And it converts a **fourth** workload surface a plan-check audit found and the original scoping missed entirely: `SupDashboard`'s own "עומס השומרים" card on the supervisor's home screen, which renders the identical `shifts.filter((s) => s.assignedGuards.includes(g.id)).length` shape the reports table is being fixed for — one screen away from the one this plan already knew about.

Purpose: a transparency feature that reports a wrong figure is worse than no transparency, because it buys trust it cannot honour. A screen whose nav label promises fairness and whose table shows a shift count is that failure, on the one screen a supervisor opens specifically to check whether the week was fair — and the same failure sits one click away, on the very first screen a supervisor opens at all.

Output: a pure, Node-tested `loadTable()`; a pure, Node-tested `chartTheme()`; a reports screen and a dashboard card that both name roles and never colours, and both report load instead of count; and a standing `npm test` gate — symbol-based and shape-based — that fails when a fifth screen starts claiming to measure workload, by name or by inline arithmetic.

**Note on 01-02's inventory gate:** 01-02's three-file assertion (`01-02-PLAN.md:271`) is a one-time `<automated>` check inside 01-02's own plan file, not a standing check in `scripts/verify-planning.mjs` — it already ran and passed during 01-02's execution, before this plan's changes existed, so there is nothing here for this plan to conflict with. Task 3 below simply re-asserts the file-match count at its new, correct value, for the record.
