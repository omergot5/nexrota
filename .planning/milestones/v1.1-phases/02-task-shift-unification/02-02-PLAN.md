<objective>
Give a task the two hour columns it needs, capture them in the form for single-day tasks only, and carry them through the one file that is allowed to know database column names.

Purpose: UNIF-01 is the input half of the phase. Plan 02-01 built an engine that can measure a task's hours; this plan is where those hours come from. It is also where UNIF-04 is enforced permanently: the migration adds two nullable columns and touches no existing row, so every task created before today keeps NULL in both and is frozen outside the engine by construction rather than by a flag someone has to maintain.

Output: `supabase/migrations/0005_task_hours.sql`, a two-field extension to the task mappers in `src/lib/api.js`, two conditionally-rendered time inputs in the `TaskMgmt` modal, and an updated schema document.

**Decision IDs.** Numbering and full text are in `02-01-PLAN.md` § objective; `02-CONTEXT.md` rows 1–6 map to D-01…D-06 in order.

- **D-01** — only a single-day task may carry hours; this plan gates the form on `isSingleDayTask` and strips hours from anything multi-day before it can be saved
- **D-05** — the hour fields open empty, with no default. A manager who types the hours explicitly is safer than one who accepts a guess: a task with hours enters the engine and changes people's load, and a wrong default would do that silently
- **D-06** — `gs_task_templates` gains no hour columns this cycle. Template-created tasks span the whole week and are therefore multi-day and frozen, which is consistent rather than a gap
</objective>
