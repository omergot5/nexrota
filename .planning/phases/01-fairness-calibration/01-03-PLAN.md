<objective>
Bring the third supervisor-facing fairness surface — the reports screen — onto the same unit as the engine, and close the inventory gate that was structurally blind to it.

`src/components/SupervisorApp.jsx:39` labels the reports nav item `hint: "עומסים, לילות והוגנות"` — loads, nights **and fairness**. The screen behind that label, `src/components/supervisor/Analytics.jsx`, computes per-person workload with the exact formula this phase exists to eliminate: `total: mine.length` (a shift count) and `hours: Math.round(...)` (unweighted hours), rendered side by side in the per-person table at lines 169–175. Neither 01-01 nor 01-02 touches this file. The phase goal line is "נטל, בכל מנוע **ובכל מסך**" — every engine and every screen — and this screen currently contradicts it while advertising fairness in its own nav label.

This plan does three things. It moves the table onto weighted load by delegating every figure to `teamAverages()`, the pure function `GuardApp.jsx` already uses, so the reports screen cannot hold a private formula. It resolves the Recharts colour constraint properly rather than by deletion: the existing code comment states the real reason those five colour values are hardcoded — *"Recharts styles its axes and tooltips through JS props, not CSS, so it cannot read our custom properties — it has to be told the theme"* — and that constraint is true, so the capability moves into a design module that reads `tokens.css` at runtime instead of being removed. And it widens the fairness-surface inventory gate to cover `shiftLoad`, `shiftHours` and the new `loadTable`, so a workload table measured in the wrong unit cannot appear in `src/components/` unseen again.

Purpose: a transparency feature that reports a wrong figure is worse than no transparency, because it buys trust it cannot honour. A screen whose nav label promises fairness and whose table shows a shift count is that failure, on the one screen a supervisor opens specifically to check whether the week was fair.

Output: a pure, Node-tested `loadTable()`; a pure, Node-tested `chartTheme()`; a reports screen that names roles and never colours; and a standing `npm test` gate that fails when a fourth screen starts claiming to measure workload.

**This plan's inventory gate supersedes 01-02's.** 01-02 task 2's gate (`01-02-PLAN.md:271`) asserts that exactly three component files match `teamAverages|fairnessPlan|fairnessHint|loadShareHint`. That pattern is structurally blind to precisely this screen — Analytics computes workload from `shiftHours` and matches none of those four symbols. After this plan the narrow pattern legitimately matches **four** files, not three, because Analytics now consumes the shared hint helper. 01-02 is frozen, so its narrower gate is not edited; the widened gate is restated in full inside this plan's verify blocks and is the authoritative one from here on. Both the widened list and the corrected narrow list are asserted below, so the supersession is machine-checked rather than described.
